# 从 Alpha 到 10 分产品：执行与验收方案

> 文档版本：1.0
> 适用项目：Termcloak（原 `claude-novel`）0.2.0-alpha.1
> 当前阶段：技术 Alpha
> 目标阶段：可公开发布、可持续维护的 1.0 产品

## 1. 最终目标

把当前“能运行、效果像”的终端小说 Demo，做成一个可靠、可信、易安装的本地终端阅读器：

- 终端界面高度接近现代 AI 编程助手的交互节奏，但不冒充任何官方产品。
- 在 macOS、Linux、Windows 常见终端中稳定运行，不滚屏、不乱行、不遗留 raw mode 或隐藏光标。
- 支持中文小说的常见编码、章节、搜索、书签、书架和稳定进度。
- 默认完全本地、无联网、无遥测，不执行书籍内容，不泄露工作目录信息。
- 一条命令即可使用，具备完整的测试、CI、文档、许可和发布产物。
- 保持“纯终端、轻量、启动快、可在 SSH/tmux 中使用”的差异化，不演变成笨重的通用电子书应用。

建议公开定位：

> A private, local-first reader disguised as a generic AI coding session, built for terminals.

中文定位：

> 一款本地优先、纯终端运行、采用通用 AI 编程会话外观的轻量阅读器。

## 2. “10 分”的量化标准

总分 100 分，最终得分除以 10 即产品评分。任何发布阻断项未通过时，即使总分达到 90，也不能发布 1.0。

| 维度 | 权重 | 10 分状态 |
| --- | ---: | --- |
| 产品定位与差异化 | 10 | 一句话能说清价值；不依赖第三方商标；与 IDE 阅读器、通用 TUI 阅读器区别明确 |
| AI 会话拟真与交互 | 15 | 输入框、状态、动画、提示、命令、遮罩形成统一系统；所有可见提示都真实可用 |
| 阅读能力 | 15 | 中文编码、章节、搜索、跳转、书签、书架、稳定进度完整可用 |
| 终端可靠性 | 20 | 不滚屏、不越界、Unicode 正确、缩放稳定、所有退出路径恢复终端 |
| 跨平台兼容性 | 10 | macOS/Linux/Windows、常见终端、tmux/SSH 有自动或人工验收证据 |
| 隐私与安全 | 10 | 默认离线、内容转义、进度安全写入、敏感信息不进入遮罩或日志 |
| 测试与工程质量 | 10 | 单测、快照、PTY 端到端、CI、回归用例和可诊断错误完整 |
| 安装、文档与发布 | 10 | npm/GitHub Release 可复现，许可、变更日志、演示和卸载说明齐全 |
| **合计** | **100** | **达到公开稳定版标准** |

### 发布阻断项

以下任何一项失败，1.0 评分上限为 7.9：

- 正常退出、异常退出或收到信号后，终端未恢复光标、颜色、raw mode 和备用屏幕。
- 动画或翻页造成持续向上滚屏、越过终端最后一行或出现无法消除的残影。
- 中文、Emoji、组合字符、框线字符导致可复现的错位或截断。
- 小说正文中的 ANSI/OSC/控制字符能够注入终端命令、标题、剪贴板或链接。
- 改变窗口尺寸后进度明显跳跃，或进度文件可能被并发写坏。
- UI 展示了不可用的命令、快捷键或虚假的功能承诺。
- 安装包缺少真实许可证、来源地址、隐私说明或可复现测试结果。
- 产品名称、包名或默认界面可能使用户误认为是 Claude、Codex 或其他厂商的官方产品。

## 3. 产品边界

### 3.1 1.0 必须做

- TXT：UTF-8、GBK、GB18030 自动识别，也允许用户手动指定编码。
- 可靠章节解析：章、回、卷、部、篇，以及序章、楔子、番外、后记等常见标题。
- 阅读：前后页、前后章、跳章、百分比跳转、全文搜索、书签、最近阅读。
- 输入框：斜杠命令、中文命令、历史记录、补全和错误提示。
- 动画：多种运行状态、降级模式、减少动画选项，且全部原地刷新。
- 遮罩：一键进入和恢复；默认使用脱敏模板，不读取项目正文。
- 持久化：稳定内容锚点、原子写入、迁移机制、禁用保存选项。
- 发布：npm 包和 GitHub Release；安装、升级、卸载路径完整。

### 3.2 1.0 可以做，但不能阻塞发布

- EPUB 支持，可通过可选适配器实现。
- 只读工作区上下文遮罩，例如目录名、分支名和脱敏后的 `git status` 摘要。
- 多套中立主题，例如 `agent-dark`、`agent-light`、`minimal`。
- 单文件可执行程序或 Homebrew/Scoop 安装。

### 3.3 暂不做

- PDF 排版、图片漫画、在线书城、账号系统、云同步。
- 调用真实大模型生成内容。
- 自动扫描浏览器、聊天软件、剪贴板或未明确授权的工作文件。
- 使用 Claude/Codex 的官方图标、名称或一比一复制其品牌素材。

## 4. 技术原则

1. **可靠性优先于零依赖**：可以引入极少量、经过审计的依赖解决 Unicode 和编码问题；不要为了“零依赖”维护一套不完整标准。
2. **固定视口模型**：渲染器只拥有当前终端视口，永远不通过追加日志制造动画。
3. **单一清理出口**：所有正常、异常、信号退出都必须经过同一个 `TerminalSession.close()`。
4. **内容永不可信**：小说标题、正文和文件名统一清除 ANSI、OSC、C0/C1 控制字符后再渲染。
5. **进度与排版解耦**：保存字符、段落或内容锚点，不保存由窗口大小决定的页码作为唯一位置。
6. **功能必须可验证**：界面显示的每条 Tip、快捷键和命令都由同一份命令注册表生成。
7. **默认不采集**：无网络、无遥测、无自动更新请求；任何联网能力必须显式开启。
8. **核心小而适配层可扩展**：终端、书籍解析、进度、命令和主题分层，格式扩展不侵入渲染器。

## 5. 目标架构

```text
bin/novel-code.js
        │
        ▼
Application Controller
  ├── TerminalSession       raw mode、备用屏幕、信号、恢复
  ├── ViewportRenderer      帧模型、差分绘制、尺寸变化、降级
  ├── CommandRegistry       命令、别名、补全、帮助、Tip
  ├── ReaderState           当前书籍、位置、书签、搜索、自动翻页
  ├── BookAdapter           TXT / EPUB 可选适配器
  ├── ContentSanitizer      ANSI、OSC、控制字符、Unicode 分段
  ├── ProgressStore         稳定锚点、原子写入、迁移、文件权限
  ├── ThemeEngine           中立 AI 会话皮肤、无颜色、减少动画
  └── Diagnostics           --doctor、兼容性与错误报告
```

状态管理使用显式状态机，避免动画、输入、自动翻页和遮罩互相抢占：

```text
BOOTING → READING ↔ INPUTTING
              ↕         ↕
          SEARCHING   THINKING
              ↘         ↙
               COVERED
                  │
               CLOSING
```

`CLOSING` 是终态；任何状态都可以因为退出键、信号或异常进入它。

## Phase 1：终端可靠性重构（P0）

目标：把当前最容易“翻车”的终端层做成可证明可靠的基础设施。

- [x] `TERM-001` 抽出 `TerminalSession`，集中管理 raw mode、备用屏幕、光标和颜色。
- [x] `TERM-002` 为 `SIGINT`、`SIGTERM`、`SIGHUP`、未捕获异常和 Promise 拒绝建立统一清理流程。
- [x] `TERM-003` 处理 `SIGWINCH`，窗口变化后重新分页并保持内容锚点。
- [x] `TERM-004` 使用正确的 `wcwidth` 与 grapheme cluster 计算显示宽度。
- [x] `TERM-005` 建立固定视口和帧缓冲，只重绘变化行；绝不触碰终端保留的最后一格。
- [ ] `TERM-006` 限制动画刷新频率，合并连续按键，处理 stdout backpressure。
- [x] `TERM-007` 支持 `--no-color`、`NO_COLOR`、`--reduced-motion` 和非 TTY 降级。
- [x] `SAFE-001` 清除正文、标题、文件名中的 ANSI、OSC、C0/C1 和危险控制序列。
- [x] `SAFE-002` 终端目录使用 `0700`，进度文件使用 `0600`，不记录正文。

验收标准：

- 连续运行 2 小时，无持续滚屏、错行、明显内存增长。
- 在 60×16、80×24、120×40 三类尺寸中，边框和输入框不越界。
- 每秒改变窗口大小并持续 30 秒，不崩溃、不丢失当前位置。
- `q`、`Ctrl+C`、`SIGTERM`、模拟异常退出后，终端均恢复正常。
- 包含恶意 ANSI/OSC 内容的 TXT 不能改变窗口标题、剪贴板或终端状态。

## Phase 2：稳定阅读内核（P0）

目标：从“分页展示文字”升级为真正可日常使用的阅读器。

- [ ] `BOOK-001` 重构为 BookAdapter，统一书籍元数据、章节和内容位置接口。
- [x] `BOOK-002` 支持 UTF-8/GBK/GB18030 检测和 `--encoding` 覆盖。
- [ ] `BOOK-003` 扩展章节规则，并允许通过配置覆盖正则。
- [ ] `BOOK-004` 大文件采用增量读取或索引，避免一次性复制全部内容。
- [x] `POS-001` 进度改为 `bookIdentity + chapterId + contentOffset + contextHash`。
- [x] `POS-002` 文件移动后通过内容指纹继续识别，文件修改后尝试上下文重定位。
- [x] `POS-003` 使用“临时文件 → fsync → 原子替换”保存进度，并保留上一个有效版本。
- [x] `READ-001` 增加章节目录、跳章、百分比跳转和返回原位置。
- [x] `READ-002` 增加全文搜索、上一个/下一个结果和结果高亮。
- [x] `READ-003` 增加书签、书签备注和最近阅读书架。
- [x] `READ-004` 自动翻页支持间隔设置、暂停条件和清晰状态反馈。

验收标准：

- 改变终端尺寸、字体或主题后，恢复位置误差不超过当前段落。
- 同一文件移动路径后仍能识别；正文小幅修改后能定位到相邻上下文。
- 100 MB TXT 启动到可阅读界面的 P95 小于 1 秒，内存峰值不超过 150 MB。
- 中英文混排、Emoji、空行密集、超长段落和无章节文件均可阅读。

## 7. 兼容性验收矩阵

| 平台 | 终端 | 最低验收 |
| --- | --- | --- |
| macOS | Terminal、iTerm2、WezTerm、Ghostty、VS Code Terminal | 输入、动画、resize、退出恢复、中文宽度 |
| Linux | GNOME Terminal、Konsole、WezTerm | 同上，并测试 SSH 远程运行 |

| Multiplexer | tmux | resize、detach/attach、颜色、退出恢复 |

每个平台至少保留一次自动测试日志或人工验收记录。README 只能宣称已完成验证的平台，不使用“理论支持”。

## 8. 性能预算

| 指标 | 1.0 门槛 |
| --- | ---: |
| 5 MB TXT 冷启动到首帧 P95 | ≤ 300 ms |
| 100 MB TXT 冷启动到可阅读 P95 | ≤ 1 s |
| 普通翻页响应 P95 | ≤ 50 ms |
| 遮罩/恢复响应 P95 | ≤ 100 ms |
| 动画帧绘制 | ≤ 16 ms，不超过 10 FPS |
| 动画空闲 CPU | 平均 ≤ 3% |
| 100 MB TXT 内存峰值 | ≤ 150 MB |
| 连续 2 小时运行 | 无明显持续增长，无滚屏 |
| npm 解压体积目标 | ≤ 1 MB；超出需说明原因 |

性能数据在 CI 或发布报告中记录机器、Node 版本、终端和样本大小，不能只写“很快”。

## 9. 安全与隐私清单

- [ ] 默认没有 HTTP、DNS、遥测、崩溃上传和自动更新请求。
- [ ] 正文和标题经过终端控制序列清理。
- [ ] 不执行书籍中的代码、命令、链接或模板表达式。
- [ ] 工作区遮罩必须显式启用，并仅读取白名单元数据。
- [ ] 日志和 `--doctor` 不输出正文、完整工作路径和环境变量。
- [ ] 进度文件目录和权限正确；写入失败不会覆盖最后一个有效版本。
- [ ] 依赖有锁定版本、许可证记录和安全审计。
- [ ] README 说明数据保存位置、删除方法和 `--no-save` 行为。
- [ ] 示例文本拥有明确授权，不随包分发第三方小说内容。

- repy：<https://github.com/newptcai/repy>

不与竞品正面比拼“支持最多格式”，而是建立四个优势：

1. **终端原生**：不要求 IDE 或桌面 GUI，可在 SSH 和 tmux 使用。
2. **拟真统一**：不是给正文套一层颜色，而是完整的输入、命令、状态和遮罩系统。
3. **稳定可信**：把无滚屏、异常恢复、Unicode 和内容安全作为核心产品指标。
4. **轻量私密**：启动快、默认离线、无账号、无遥测、安装和卸载简单。

竞争力不是“像某个产品像得最像”，而是“在不使用其品牌的前提下，仍然让用户一眼理解这是 AI 编程会话，并且每天使用都不出故障”。

## 12. 推荐执行顺序

1. 品牌与仓库基线。

## 13. 每个任务的完成定义

任务只有同时满足以下条件才允许勾选：

- 代码已实现，且没有把无关改动混入同一提交。
- 新行为有单元测试；涉及终端交互的行为有 PTY 或人工验收证据。
- README、帮助或命令提示已同步更新。
- macOS、Linux、Windows CI 没有新增失败。
- 失败时有明确错误信息，不静默吞掉异常。
- 没有新增品牌、隐私、安全或兼容性风险。
- `npm pack --dry-run` 内容符合预期。
- 变更记录已写入 CHANGELOG。
